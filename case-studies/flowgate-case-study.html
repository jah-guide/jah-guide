FlowGate — SLA service-request workflow

Systems Analyst case study · Bohlokoa (jah-guide) · Northvale Shared Services (composite) · Next.js portfolio prototype

Problem

IT and operations requests arrive via email, chat, and ad-hoc forms. Intake is manual, approvals live in spreadsheets, and leadership discovers SLA breaches only after escalations.

PainImpact
Fragmented intakeDuplicate work, lost context
Informal triageWrong priority assigned late
Unclear approval pathStalls between manager and director
Reactive SLA reportingBreaches found after customer impact

Stakeholders

StakeholderKey need
Business requesterStatus visibility, clear reject reasons
Ops analystSingle queue, triage tools, SLA signals
Line manager / DirectorSequential gates with audit trail
Head of Shared ServicesLive breach and queue posture

To-be process

Requester     Ops analyst      Manager         Director
    |              |               |               |
    v              v               v               v
[Intake] ---> [Triage/route] -> [Approve/Reject] -> [Approve/Reject]
    |              |               |               |
    +--------------+---------------+---------------+
                          |
              SLA: P1 4h · P2 24h · P3 72h (from createdAt)
                          |
            On Track  |  At Risk (≤25% left)  |  Breached

States: submitted → pending_manager → pending_director → approved | rejected
